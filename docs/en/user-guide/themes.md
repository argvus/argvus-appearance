ARGVUS provides twenty-four official theme families, each with Sticky and Float modes. In **Control Center → Appearance → Themes**, open **Official Themes**, then choose **Dark** or **Light**, a family and its mode:

- **Dark** — One Dark, Dracula, ARGVUS Dark, Silver, Slate, Universe, Gruvbox High, Gruvbox, Catppuccin Latte, Rosé Pine, Tokyo Night, Solitude, Sunset, Hackerman and Monokai Dark.
- **Light** — ARGVUS Light, GitHub, Solarized, One Light, Flexoki Light, Everforest Light, ARGVUS Kanagawa Lotus, Nord Light and Light Gruvbox.

Custom imported profiles remain in a separate **Custom Themes** entry. The official catalog contains every packaged appearance family; each family exposes both **Sticky** and **Float**.

Press `SUPER + Shift + T` to open the Rofi selector, then choose **Dark** or **Light**, a family and **Sticky** or **Float**. Press Right to advance and Left to return one level; Escape closes the selector. The same hierarchy is available in **Control Center → Appearance → Themes**. Imported custom profiles remain under a separate **Custom Themes** section. The Control Panel can also expose a quick appearance action. Select a highlight color from **Control Center → Appearance → Accents** with the color picker, or use:

```sh
sh /usr/share/argvus/appearance/sh/accent-switch.sh '#17d174'
```

The color accepts a valid six-digit RGB value. An explicit custom accent survives theme selection; theme-owned accents follow the selected manifest. **Reset to theme default** clears the custom-override state. Borders and other accent consumers are projected from the selected theme. The logical state is stored in `$XDG_CONFIG_HOME/argvus/config.json`; `.active-theme`, `.accent-color` and `.accent-custom` are legacy migration inputs only, and every file below `$XDG_CONFIG_HOME/argvus/data/generated` is written by `argvus-config` alone.

Theme changes propagate to the compositor, shell surfaces, applications, lock screen and notifications. See [wallpapers](./wallpapers/) and [configuration and state](../../developer-guide/architecture/configuration-and-state/).

`argvus-config` projects the theme into every ARGVUS-owned surface — compositor, Waybar and telemetry profiles, Quickshell, Rofi, Dunst, Hyprlock, Yazi, Superfile, terminal and Qt profiles, GTK, the removable-devices stylesheet and the Hyprtoolkit overlay colors — and then `accent-switch.sh --apply` reconciles the external consumers. Float therefore applies rounded Rofi windows as well as rounded compositor, taskbar and shell surfaces; Rofi actions launched by ARGVUS resolve this projected configuration rather than the packaged Sticky default.

The Control Panel reloads its theme only after the canonical projection has completed. Its generated theme file is recreated automatically when missing, so reopening or reapplying a theme does not require editing generated files and does not restart the panel when the effective theme is unchanged.

## Custom profiles

In **Control Center → Appearance → Themes**, profile actions can export the current ARGVUS appearance to a timestamped `.tar.gz` file in your home directory. The archive contains the allowlisted logical appearance files and, when the current wallpaper can be described and read, a validated wallpaper payload. Generated runtime output is regenerated when the profile is applied; it is not the source of truth in the archive.

Import a `.tar.gz` from the same Themes page. ARGVUS stages and validates the archive, installs it as a custom profile and makes it available for selection. A name collision receives a distinct profile identity. Applying the custom profile restores its theme state, accent/effects/layout overrides and included wallpaper when the original wallpaper path is no longer available. If a profile wallpaper cannot be restored as a file, the profile is applied without that custom wallpaper and the stale marker is removed.

The profile is an `argvus-theme-profile` version 4 archive when `argvus-config` is available. It contains an allowlisted manifest, checksums and a canonical `config.json` appearance scope for the active theme, layout, effects, fonts and Control Panel cards. Legacy version 2 and 3 archives remain importable, but their native dot-files are converted and are not installed as runtime state. Generated Hyprland, Waybar or shell output is recreated when the profile is applied; it is not copied into the profile as authoritative configuration.

The profile also carries the active theme's per-surface transparency and blur values for Taskbar, Control Panel and Widget Telemetry. Values saved for inactive themes are intentionally not exported.

When importing, ARGVUS first validates the archive before installing it. The embedded wallpaper is restored under the current user's home when possible. If the original home-relative path is unavailable, ARGVUS falls back to the user's pictures directory or `~/Pictures/ARGVUS`; a filename collision receives an `-imported-N` suffix. Import fails when the archive contains an invalid or unreadable wallpaper payload, rather than creating a profile that points to a missing file.

Importing and applying are separate steps: importing adds the profile; selecting it applies it. Applying a custom profile reloads the affected session surfaces. Deleting the active custom profile falls back to `argvus-dark`.

## Layout modes

The current Hyprland defaults are:

| Setting | Sticky | Float |
| --- | ---: | ---: |
| Internal window gap | `2` | `10` |
| Outer gap on each edge | `0` | `18` |
| Window rounding | `0` | `4` |
| Taskbar/shell margin | near the edge | `18` |

These are mode defaults. An explicit theme selection resets the mode-owned fields (`gaps_in`, all outer gaps, taskbar/telemetry margins, `rounded`, `rounding` and `thickness`) and records `layout.variant` as `sticky` or `float`. `waybar_pos`, `taskbar_utility_group`, custom accents and custom wallpapers remain independent preferences. Manual mode-owned edits remain active until the next explicit theme selection.
